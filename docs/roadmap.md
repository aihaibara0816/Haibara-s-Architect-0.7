# 从工作流走向可用 Agent

0.6 已经有稳定输入、明确约束、结构化提案、工具分发、新 run 留存与验证。下一步以能验收的小闭环推进：

| 顺序 | 具体工作 | 完成判据 |
|---|---|---|
| 1 | 统一空间计划到一个小建筑适配器 | 同一请求能生成 NBT；模块ID映射到实际方块；冻结模块差分为零 |
| 2 | 补齐内饰/家具依赖与方块状态 | 四种固定小样可独立生成；门/家具/吊顶都有最终NBT检查与游戏截图 |
| 3 | 将材质、灯光、植物通道接到几何 | 改一通道只影响声明范围；增删无关模块不引起其他随机变化 |
| 4 | 地形先行的场景消费者 | 明确高程输入、道路坡度/净空、岸线与铁路保留范围；先做一小片街区 |
| 5 | 把最终产物真正渲染并复核 | 图像存在、摘要相符、视角覆盖明确；人工反馈可定位构件 |
| 6 | 有限工具 Agent | 宿主管理模型、工具allowlist、预算、失败重试和暂停点；每次修改可追踪 |
| 7 | 游戏内检查回传 | 在测试存档验证碰撞、连接、照明和尺度；不以离线通过代替 |

优先的小闭环可以是“一间阅读室”或“一个骑楼街模块”，不从整座城市自动建造开始。城规应先锁定岸线、地形、铁路和地标，再决定道路层级与建筑排布；广州塔与松山湖等固定条件应以约束表达，不能靠随机布置解决冲突。
