# 竖向幕墙：广州周大福 V1 实验

用户认可深圳报业大厦横向幕墙的改善后，要求用广州东塔检验竖向体系。案例位于 `cases/guangzhou_ctf`，统一由 HAF 入口生成。

本次实际复用：HAF阶段缓存、可追溯构件、稳定房间随机数、NBT写入与独立回读、状态几何预览、分片精确拼合。新增：公共竖向分层单元、显式墙柱状态、受限可配置Scene预算、避免结构碰撞与玻璃连接变化的灯槽选择。

## 图片研究的消费者

- KPF 陶土细部 → `hafusion/facade.py` 的外梃/玻璃分层；闪长岩墙柱是原版材质近似。
- 多层平面和带标高剖面、建成多向照片 → 东塔适配器的非同心轮廓和斜顶；没有把像素宽度直接当竣工尺寸。
- K11近景和连桥照片 → 暖色下段、浅色玻璃上段及独立桥底。
- 窗墙内景 → 窗后深度；未声称复原真实室内。
- LPA照明说明与照片 → 顶部及外梃线光的后续目标。本版塔冠候选灯槽均未通过无碰撞筛选，实际塔冠专用灯为0；已实现的是窗后与裙楼灯光，不能称作已还原LPA线光。室内亮暗使用游戏适配规则。

## 失败与修正

1. 初稿场景超过旧一百万格包围盒预算。显式选择两百万格预算；没有改旧案例默认值，旧深圳NBT可完全重现。
2. 直墙样板通过后，量化弧面仍出现薄玻璃接缝。栅格围护闭合不是几何表面连续的充分条件。转角加入完整玻璃填片，连续背板按楼层轮廓内缩。
3. 初稿更换灯光种子时产生509处非灯光状态差异，包括背板覆盖和玻璃片连接。这些差异没有被包装成“更丰富的细节”。现在先为明暗房间都预留无碰撞灯槽，避开玻璃片水平邻接，再决定是否点亮。公共函数为 `first_clear_slot`。
4. 一个预览PNG出现截断，成品检查逐张完整解码并核对NBT哈希，失效图片不进入交付。
5. 源包独立复现发现：灯光模块新增辅助函数时提升版本号，意外改变了旧深圳案例的随机数输入，连家具也发生变化。随机数命名空间现与模块版本解耦：旧调用默认固定 `room-lighting-0.1`，东塔V1显式固定 `room-lighting-0.2`，两者都必须复现各自已发布NBT。补入旧房间的金标准与模块升级不重新抽样的回归测试。

## 下一建筑继续用的验收

- 直段、转角/折面、底部接口各有可见样板；不能只看正面。
- 先检查轮廓、凹槽和材料前后顺序，再数细节。
- 相同参数NBT字节一致；更换灯光种子只改变灯光格位，不能改变玻璃连接或结构。
- 所有对外图片读取最终NBT，并标明剖切、近似材质和未游戏验证状态。
- 图源不按固定数量截断；检查实际构件覆盖和重复，不以图片数量当质量指标。

该成果是案例与程序规则积累，不等于通用视觉模型训练完成。东塔V1的用户认可、游戏内玻璃连接和墙柱材质效果仍待后续验收。
