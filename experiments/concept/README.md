# 立面计划器实验包

**状态：experimental（实验性）。** 两份脚本按审计快照原字节复制，未修改算法。它们供人工确认输入后的手动试验，不默认执行，也不会随导入自动运行命令。

## 包含内容与依赖

| 文件 | 用途 |
|---|---|
| `scripts/plan_openings.py` | 在人工确定的立面安全区间内生成窗组、承台和植栽有无的 JSON 计划 |
| `scripts/plan_variation.py` | 为人工定义的立面面板分配玻璃色差、旧化强度及花槽候选选择 |
| `examples/opening-groups-example.json` | 新编写的三组开窗输入示例，包含横窗、竖窗与固定范围的门厅玻璃窗组 |
| `examples/variation-example.json` | 随已审脚本保存的原始材质变化示例，按原字节复制 |

两份脚本仅使用 Python 标准库，无需安装第三方 Python 包。实际验证版本为 **Python 3.12.14**；未承诺其他 Python 版本的兼容性。此包没有安装器、默认任务、内饰实验室、渲染器或 NBT 消费适配器。

## 手动运行

在本包根目录打开终端，确认 `python` 指向你要使用的 Python 环境，再按需运行：

```sh
python scripts/plan_openings.py examples/opening-groups-example.json --out outputs/opening-groups-plan.json
python scripts/plan_variation.py examples/variation-example.json --out outputs/facade-variation-plan.json
```

脚本会创建输出父目录，并写入 JSON。若目标文件已存在，脚本会覆盖它；需要保留上一版时请换一个输出文件名。输出路径由你指定。

示例是演示数据。示例中的支撑引用、允许开窗区间和通道声明并不对应已经核验的实际建筑。用于项目之前，应由人确认空间用途、结构、门洞、通路、楼层高度及立面局部轴方向。

## 输入与结果的边界

### 窗组计划

`allowed_u_m` 是人工给定的安全水平区间；`base_u_m` 是其中的基础窗组范围。u 是立面局部水平坐标，单位米；`sill_m` 与 `head_m` 是相对所在楼层的高度。脚本不自动转换世界坐标，也不推断朝向或楼层绝对标高。

`openings` 是这次计划的开窗几何真源，应替换旧逐开间开窗矩形；不要与旧矩形叠加。非 `screen` 窗组可以启用 `allow_ledges`，但非空 `support_ref` 只是一条作者引用，不是结构、固定件或排水验证。支撑与避让必须另行检查。

已知限制：

- **窄 fixed 窗组扩宽。** 当前算法仍对宽度施加最小 1.1m 规则。当 `fixed: true`、基础宽度处于 0.8m 至不足 1.1m 且允许区间较宽时，输出范围可能扩大。例如 allowed `[0,5]`、base `[1,1.8]` 会得到 `[0.85,1.95]`。此包保留已审源码，未修复该行为；不要依赖这种窄窗组的精确范围锁定。
- **fixed 不冻结全部几何。** 对常规跨度，fixed 固定窗组范围与窗数；更换 seed 仍可能改变单窗宽、窗台/窗头及承台。需要完整冻结时，应保存并直接复用确认后的输出。
- 窗组输入的 schema/type 校验不完整。请使用示例那样的字符串 ID、整数 seed、正整数 count_hint、有限数值和布尔开关，不能把脚本未报错等同于输入合格。
- 输出尚需门洞、逃生、采光、三维碰撞及真实支撑检查；本脚本不从图片识别可开窗区域。

### 材质与花槽计划

输入 schema 为 `HAA_facade_authoring/0.1`。玻璃点缀按每区域合格玻璃面板数乘目标比例后向下取整，按面板数量计，不按实际面积计。`protected` 禁止点缀和旧化，但并不承诺保留所有原材质字段；被归入玻璃系统的受保护面板仍会写入区域主玻璃材质。

**`planter_density` 是组级选取概率，不是精确数量或比例配额。** 同一 `group_id` 的合格候选共享选择结果，可能整组选中或整组不选。跨区域请使用全局稳定且不冲突的 group ID。`support_confirmed` 和 `clear_of_routes` 仅是作者声明；脚本不会验证真实支撑或碰撞。

旧化只输出强度与 `surface-mask-required` 提示，没有生成雨痕、接缝、窗台下流挂等空间遮罩，也不是材料物理老化模型。玻璃名称还需要下游映射和方块状态检查，不应随意交换玻璃块与玻璃片。

## 确定性与交接

同输入、同 seed 可复现。输入数组重排不会扰动结果；新增独立窗组或全新区域可保持既有分配。向同一区域增删面板可能改变该区域的玻璃点缀配额与选择。两个脚本的 hash 序列化方式不同，不承诺共享同一随机序列。

交接时请保存输入、seed、算法版本、参数及完整输出。两脚本生成的是待确认计划：**不是 NBT 生成器，不是 HAF 引擎适配器，也不是游戏验证工具。** 数据检查、几何检查、视觉审阅、引擎消费和游戏检查应分别记录。示例执行成功不代表建筑可建造或视觉效果已通过。
