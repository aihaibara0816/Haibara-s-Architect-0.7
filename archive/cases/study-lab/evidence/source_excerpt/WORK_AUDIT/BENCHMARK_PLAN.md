# 公平对照、跨建筑验证与失败案例

本轮已经执行的只有 `logs/` 和 `experiments/run01/` 记录中的实验。下面的建筑级对照都是下一轮方案，不包含虚构效果分或运行结果。

## 1. 两条研究轨道

| 条件 | Track A：受控模块对照 | Track B：完整研究流程 |
|---|---|---|
| 输入 | V5 与候选使用同一图片、模型、尺寸锚点、来源许可状态 | 可追加搜索或新模型，逐条登记 |
| 尺度/范围 | 同一比例、目标尺寸、1F 以上范围与平台接口 | 允许提出新假设，但分开报告 |
| 算法 | 一次只更换一个模块；组合实验明确命名 | 可以同时改变资料与流程 |
| 生成/展示 | 同游戏/导入器/方块注册表/资源包/光影/相机/天气/分辨率 | 条件变化都记录，不能与 A 混算 |
| 结果 | 几何、占用、状态、所有权、空洞、文件与成本 | 另计搜索时间、图片数、人工修订分钟、API 费用 |
| 可推出的结论 | 特定模块在冻结案例上造成的差异 | 整体流程的效率与质量变化；不作单模块因果归因 |

新增照片以后变好，应在 Track B 讨论；不能同时换几何算法后把改善全部归功于图片数量。

## 2. V5 作为当前基线

已经具备：完整代码、参数、模型/资料记录、原 NBT、固定预览、反馈和历史失败记录；原归档及 NBT 哈希已核验。本轮独立读回 128×282×232、118,566 非空气单元，9 分块精确重组。

适合比较：输出可复现性、塔体/场地接口、已留出的功能空区、构件归属、相对标高、灯光块数量、分块、局部参数修订与区域外变化。

不能当真值：未经测绘的场地曲线/标高、缺校准的照片相机、46 等距环梁、核心接触处闭环、真实室内布局、游戏可行走与实际光照。历史 `15 checks pass` 不能代替这些证据。

新 run 前还需：固定 V5 用到的准确输入子集及相机参数；从已保存研究中提取明确 component/attribute 评价点；核对目标游戏配置；为测试模块预先约定允许偏差与失败条件。无需让用户重新上传现有 SKP/图片。

历史 V1 可保留为初始尺度、参数化近似与 NBT 输出基线，不能作为真实格构几何真值。V2A/V2B 是路线实验：执行时纯图片路线不得读取模型或含模型信息的导出；开发者已看过模型，应明写非盲测。后续公平双版本试验需冻结共同输入、尺度/范围/调色板/相机，记录到底改了资料、算法还是两者。

## 3. 建筑分组与 holdout

| 案例 | 角色 | 研究目标 | 独立性要求 |
|---|---|---|---|
| 广州塔 V5 与局部段 | 开发/主对照 | 收腰、扭转、开放框架、塔冠、平台接口 | 不用它独自证明通用能力 |
| 便利店/低层房间夹具 | 开发 | 1:1、门洞、薄墙、楼梯净高 | 解析夹具只证明工程正确性 |
| 台北 101 | 开发迁移 smoke test | 重复模块、退台、冠部节奏 | 不把重复层数写进通用默认 |
| 中国尊 | **预先留出** | 不同高层截面、外形与框架 | 首轮参数冻结前不用于调参 |
| 中山纪念堂 | **预先留出** | 对称/台基/复合屋顶/檐口 | 缺相应构件语法时允许明确失败，不用方盒子过关 |
| 广美教学区 | 场地开发 | 多栋、连廊、庭院、道路和高差 | 增加另一个未调参校园才可验证场地泛化 |

若针对 holdout 失败修改了规则，该建筑就转入开发集，另选新 holdout。单一新建筑通过只能称迁移 smoke test；要作更可靠结论，每类至少再准备 2–3 个独立建筑，明确样本规模。

## 4. 测量与预定验收

| 层级 | 测量 | 初轮验收/失败门槛（提案） |
|---|---|---|
| 来源 | source_id/哈希/用途/年代/状态/许可，未决冲突数 | 执行参数必须有来源或明确 estimated；同级冲突不能静默执行；转载不增加独立支持 |
| 配准 | 拟合点与留出点残差，尺度/轴/原点 | 先设目标单位阈值；共线、镜像或非均匀拉伸不得偷偷通过；无对应点则 not_tested |
| 关键尺寸 | 总高、外宽、塔腰/冠部截面、平台标高 | 建议开发夹具关键边界偏差 ≤1 格；实际建筑按既定比例和测量精度单独确认；不能只报平均误差 |
| 外轮廓 | 同投影轮廓 IoU、边界距离 | 先校准相机、建筑掩膜与可见区域；夜景/反射/遮挡单列；没有可比条件不输出伪数值 |
| 负空间 | 必须开口、竖井/庭院、内外层间隙、连通 | 指定保护区域中新增实体数=0；必要开口不能堵塞；细杆失联按单构件记录 |
| 通行 | 入口到指定点的连接、净高/台阶 | 静态夹具两格净高与路径通过；游戏碰撞验证另列，不能用 flood-fill 替代 |
| 材质 | 类别、朝向、连接、透明/发光/重力规则 | 只改调色板时纯占用与非目标构件不变；非法或缺版本状态即失败 |
| 局部修订 | 区域外坐标/状态/owner 差分 | 保护区域外未授权变化=0；依赖连接件变化需预先申明 |
| 缓存 | 冷/热/局部/全量产物比较 | 同输入时 hash 与内容一致；来源/角色/参数/框架/算法变更正确失效；损坏缓存不复用 |
| NBT | 独立解析、尺寸/状态/数量、分块接缝 | 精确一致，无越界、重复或漏块；全部模块重组与完整 NBT 一致 |
| 游戏 | 导入/读回、透明、灯、水、重力、通行 | 在确认过的版本测试实例实际执行、有日志/截图；否则保持 pending |
| 效率 | wall time、峰值内存、文件体积、缓存命中、人工分钟 | 同机器、同输入，分别报告冷启动/热启动；不拿小夹具阶段数冒充速度倍数 |
| 审美 | 同镜头匿名 A/B + 构件理由 | 用户/评审分别评价轮廓、层次、材料、场地；不合成没有依据的“还原度百分比” |

## 5. 每条候选算法的最小消融

1. **量化**：同一房间/外边界，原 half-up、PlanCraft round、ceil、接口受限局部策略。报告外形增长、净空、入口位置；不能只挑成功房间。
2. **体素化**：同网格、目标尺度和材料；旧采样、BVH 表面、带厚度表面、实体填充分别测试。空心盒/庭院/细杆/倾斜薄片包含负例。
3. **证据裁决**：同一组正常、过期、单位不同、重复转载与相互矛盾的记录；比较 R0.1 与新外置裁决。真实证据需人工确认正确归类，不能只测合成字符串。
4. **缓存**：固定生成器，只加缓存；逐个更改材质、几何、接口、坐标框架、来源、算法版本；每次与冷启动全量比较。
5. **图像几何**：人工锚点基线与 VGGT 候选；使用相同图片，预留视角/控制点；把推理时间、配准误差和人工修订时间分开。

## 6. run 最少记录

`run_id, track, parent_run, code_hash, spec_hash, input_hashes, evidence_decisions, palette/registry_hash, environment, target_dimensions, scope, coordinate_frame, camera_rig, occupancy_hash, legacy_geometry_hash, ownership_hash, metrics, nbt_readback, module_reassembly, game_validation, human_review, elapsed_time, peak_memory, manual_minutes, external_cost, limitations`。

字段没测就保留 null/not_tested；不存在的旧指标不能从截图或推测补造。评分阈值、案例分组及相机在正式对照开始前冻结。
