# HA Detail Lab 0.1.0 / r02

八组建筑细部样板：现代幕墙、千禧年语汇、西式砖石、当代中式、天线、花坛、开敞框架、砖石站房与玻璃棚。

这是独立学习与验证程序。没有修改正式 HA0.3/HAFusion、V5、原七份 schem 或网站，也没有把它声明为已安装的新 Skill。本轮“学习”指案例提炼、代码规则、样板与评估记录，不是模型权重训练。样板是原创练习，不是八座现实建筑的复原。

## 查看与导入

先打开交付的 HA_Detail_Lab_Review.html。每组有相同机位的 A/B、正面、近景、夜景、俯视剖切和侧向剖切；可下载单份 NBT、材料表并导出反馈。

- A：与 B 相同的已占用格位，把建筑细构件换成相应整块；保留植物示意形状。它是消融对照，不是旧 HA0.3 的独立生成结果。
- B：实际带状态的细部版本。NBT 回读生成预览，不是 AI 想象图。
- `runs/r02/nbt/`：16 份独立 Java structure NBT，以及 1 份 B 版合并展场。单份样板均小于 48×48×48；合并展场为 168×40×68。
- `runs/r02/components/`：构件归属 sidecar。NBT 本身不保存这些语义 ID。
- `runs/r02/nbt/*_materials.csv`：精确方块状态和放置数量；半砖数字是放置的方块格数，不是合成原料预算。
- `deliverables/HA_Detail_Lab_Java_1.21.1_datapack.zip`：数据包，只有结构模板，无 tick/load 自动函数。面向 Java 1.21.1，pack_format=48。放入空白测试世界的 datapacks 后重新加载，可手动使用 `/place template ha_detail:modern_b ~ ~ ~`；其他名称见包内模板清单。未实际进游戏验证该数据包。
- NBT 包含显式空气，导入会覆盖包围盒内部。合并展场较大，工具若有限制可逐个载入独立样板。它们不是 Sponge `.schem`，不要只改扩展名。

## 运行

Python 3.10+；生成与预览网格使用 NumPy，出图还需 Pillow 与系统 `libEGL.so.1` / Mesa OpenGL。没有这些渲染依赖时，NBT 本身仍可用游戏或现有导入器查看。开发环境为 Python 3.12。可通过本机包管理器准备 `numpy`、`Pillow`。

在项目根目录执行：

```bash
python3 -m unittest discover -s tests -v
python3 tools/build_samples.py --run my_review
python3 tools/render_samples.py --run my_review
python3 tools/verify_run.py --run my_review
python3 tools/package_review.py --run my_review
```

生成器拒绝覆盖已存在的 run 目录。修改参数后另建 run，保留上一版 NBT 与哈希。`configs/samples.json` 当前开放现代、千禧年和西式样板的柱跨数量、间距等参数；其余样板的尺寸仍在独立构造函数里，不是假称全参数化的通用引擎。

## 最小接入方式与保留项

| 文件 / 层 | 本轮处理 | 下一步 |
|---|---|---|
| 原 `architect/palette.py` / `geometry.py` / `render_views.py` / `validation.py` | 未改 | 样板验收后，在保留旧接口的前提下增加有状态构件入口与预览适配；不删除原完整方块路线 |
| 现有 NBT writer / reader | `vendor/` 原样复制，校验哈希 | 继续复用，无需重写序列化 |
| `detail_lab/states.py` | 新建有限状态词表、连接和 90° 旋转、视觉形状 | 增加游戏注册表核对、局部遮挡和真实资源包模型；现有几何不是碰撞模型 |
| `detail_lab/builders.py` | 八个独立样板，复用房间、线、盒等原语 | 根据反馈改局部配方，增加转角、端头与尺度变化用例 |
| `detail_lab/mesh.py` | 从 NBT 回读产生有状态网格和近似灯光 | 游戏截屏对照；不把当前光照当作游戏渲染 |
| `tools/render_samples.py` | 原 EGL 渲染器外的剖切适配 | 按格边裁切后重新建立可见表面；不使用缺少封口的直接三角面过滤 |
| `evidence/learning_rules.json` | 十条可追溯经验及验收条件 | 通过跨建筑盲测后再回写正式 Skill，不按图片数量限制研究 |

## 评估边界与下一步

已自动验证状态序列化与回读、确定性、半砖/楼梯等几何范围、四次旋转、连接状态、未批准覆盖拦截、开敞区、灯与吊顶分层、植物支持及源文件完整性。回读器与写入器是分开的现有模块；两者仍来自同一项目，不算第三方格式认证。

还没有游戏导入、方块更新、资源包、碰撞、通行、真实光照测试。玻璃透明度、铁栏/锁链/花朵等外观是无纹理近似。本轮有限状态词表检查不是完整的 Minecraft 注册表验证；铁栏与玻璃片只对本轮支持的邻块求连接，墙、栅栏等复杂邻接没有覆盖。楼梯邻接形状尚不自动求解，需要配方明确设置。

对照不能给出“还原度提高百分比”：A/B 使用同一设计，检验的是细部表达；七个案例已参与学习，不能充当未见建筑验证。

下一步顺序：

1. 游戏验证现代幕墙、天线、花坛：加载无丢块，方向与连接正确，半砖上下无误，灯光不穿透不该穿透的结构；截图记录版本、资源包、坐标与机位。
2. 补幕墙 90° 转角、楼板端头和一间能进入的房间。验收净高、门洞、玩家行走、相邻构件更新后的状态，不用伪内饰代替。
3. 再选未用于学习的新建筑，分别做现代玻璃、砖石、中式屋面局部；研究图片不限数量，以关键构件证据覆盖为准。冻结尺度、相机和资源包，按轮廓、分格、前后层次、材料、留空、节点逐项人工评审。
4. 样板验收后才把状态词表、构件 ID 和预览适配接入 HA。若涉及替换整体工作流，先提交明确修改范围给用户确认。

## 反馈与迭代

HTML 的反馈表能保存本机草稿、导出 JSON。记录样板 ID、视角、部位、具体问题、期望和参考来源；文件包含 run 与 NBT 哈希。导出后需将 JSON 交回继续修改，它不会自动传送或改写工程。

固定本轮 r02：第一轮暴露了顶灯占据顶面导致屋面发光，以及三角面剖切缺少新暴露面的显示问题。r02 将灯移到吊顶下方，吊顶使用下半砖，并在裁切回读方块后重新生成网格。光场对半砖、楼梯和关闭的活板门保守地按整格挡光，避免直接穿过吊顶；尚不等于游戏的逐面遮光规则。夜景仍为近似，未验收为真实照明。

交付检查：13 项单元测试通过；17 份 NBT 和 96 张预览核对通过；从工程压缩包重新解压后，17 份 NBT 可逐字节复现。对比页另通过 Node 最小 DOM 环境的切换、滑块、放大、下载链接与反馈导出检查；没有执行真实浏览器排版测试。对应记录位于 run 目录。

来源：七份 schem 的完整坐标证据与原文件 SHA 在 `evidence/source_study.json`，视频与官方建筑说明链接在 `evidence/learning_rules.json`。原始输入不随本包复制。Minecraft 1.21 数据包版本与目录名称参照 Mojang 官方 1.21 更新说明；数据包目录使用 `data/ha_detail/structure/`。
