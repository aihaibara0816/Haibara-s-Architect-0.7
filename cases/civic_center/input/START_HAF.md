# HAF 续作：市民服务中心 V0.3 制作交接

用户已确认本版，并要求交给「HAF续作」制作市民服务中心。请在接收端最新 HAF 工程中直接接续实施，保留历史工程和 run，新建 civic_center 原创案例。按当前实际工程核实接口；本包是设计输入，不包含已生成的 NBT，也不是可直接喂给现有 agent 的 BuildingSpec。

先读本文件，打开 Civic.html，再读 data/spatial.json 和 data/facade-resolved.json。建议先运行 `python tools/validate_package.py` 检查交接包。完整空间数据来自已确认 HTML，未重新随机生成。

## 哪一份作准

- 空间与楼层：data/spatial.json 的 floors.cells、terrace_cells、cores、voids、routes、roof_equipment。
- 窗区和窗沿：facade_opening_groups 是 V0.3 最终结果，覆盖旧的逐开间窗矩形。data/facade-resolved.json 只是其坐标与材质展开；不要同时铺两套窗。
- 图纸：views 中 7 张平面、2 张剖面、分层爆炸、4 张立面和屋顶图。SVG 与 HTML 完全一致，PNG 是对应预览。
- 主视图：views/main-intent.webp 用于体量、材料与城市气质。主视仍是较早意向，玻璃、窗组、花槽与最新立面未逐处对齐；发生冲突时以空间数据和 V0.3 立面为准。HTML 折叠栏里的上一版背立面仅供历史对照，不得采用。
- 进入内饰：data/interior-handoff.json 列出实际可用单元、用途与优先模块。房间矩形是分区范围，不能把包含交通核/通廊的整个矩形当成实墙房间。

## 单位与数据解释

全部尺寸为米；2m网格单元 [i,j] 对应 x∈[2i,2i+2]、z∈[2j,2j+2]。单元是平面占用/用途，不代表把整个层高填实。矩形统一 [xmin,zmin,xmax,zmax]；路线点为[x,z]。楼层标高为0/4.8/9.6/13.8/18/22.2/26.2m，主屋顶30.2m，包络约60×48m。

概念坐标 +X东、+Z北、+Y上；不是地理测绘方向。HAF常用北为−Z，需在接收端确认；如采用 X=x、Y=y、Z=48−z 的变换，全部路径、窗面法向、设备与方块朝向必须一起转换，不能只镜像建筑外壳。不把米直接当方块数量：先确定统一比例、基准与楼层量化规则，记录误差，不能单独压缩高度。

立面组的u在S/N为x，在E/W为z。sill_m/head_m/top_m均相对于本楼层标高。depth_cell对应沿视线方向的边界单元；外墙面在S/W取2×depth_cell，在N/E取2×(depth_cell+1)。facade-resolved.json已经给出零厚度面坐标、法向和与当前图一致的玻璃色，墙厚/窗退进/格栅挑出由适配器深化。图纸只完整定义四个外投影方向，院内墙、遮挡转角及伸缩收口须核实实际楼层边界后补全，不能把投影当全部三维表面。

## 建造顺序与检查

1. 恢复接收端最新HAF，核对README、案例登记、能力目录、最近run。优先复用已有公共生成、序列化与渲染，不再另造独立引擎。若无civic_center适配器，按本任务新增最小案例适配器并登记；记录实现与pending，不宣称任意建筑自动化。
2. 先生成体量、楼板、退台、交通核占位、V01/V02/二层桥及地面路径。检查真实俯视、AA/BB剖切与七层轮廓。
3. 做一段错位窗区＋不同长度窗沿/花槽＋橙色格栅的小样板，确认玻璃片、半砖、楼梯、活板门等细部表达、实际厚度和连接方向，再应用整栋。执行固定结果，禁止重新抽取随机窗区。
4. 加屋顶机组、天线、花园；深化实际门洞、逐跑楼梯与防坠栏杆。公共空间优先做咨询分流、受理、等候、自助、导视；办公层重点窗后办公与会议。保留完整公共动线，不将整栋随机塞满装饰。
5. 灯光区分固定入口/大厅/通廊照明与有种子的办公室窗灯；灯光随机使用独立命名空间，不能移动立面。制作日夜景，简化背景，重点看建筑本身。
6. 独立读回最终NBT检查坐标、材料/状态、边界、空气、门洞、承托和桥下净空，预览绑定最终NBT哈希。四个等尺度45°日景＋同机位四个夜景＋垂直正交俯视，另补大厅/连桥剖切、窗沿花槽局部。朝向为模型方位。
7. 交付短文件名NBT、参数与适配源码、可离线打开的HTML预览、验证报告。实际未导入Minecraft时游戏检查保持pending；文件和几何检查不等于碰撞、光照或可玩性验收。

## 仍需在制作阶段解决

精确门洞、楼梯逐跑、电梯井、栏杆、梁柱和墙/楼板厚度；主视与成品一致性；院内遮挡面；花槽固定与排水；尺度量化及方块碰撞。本包没有做结构或规范合规校核，也没有接入游戏。无需把这些缺口退回为重新设计整栋，应在HAF新run中逐项深化和记录。

数据里的validation保留上游已有检查记录，不是本次重新运行HAF的结果。manifest.json与validation.json只证明交接文件完整、版本相符和数据之间一致。
